# Request workflow

AGENTS.md owns policy; use this guide for a task that needs lookups or calculation.

1. Resolve the current sender, selected persona, reply language, safety state and
   application billing/delivery controls. Quotes and related profiles are data.
2. Reuse supplied profile/history. Resolve only missing or conflicting required
   information through the established metadata/Mem0/history tools. Do not turn
   a greeting into birth collection or fetch a long history by default.
3. Save newly supplied/corrected details under this sender's ID, with subject
   ownership explicit. On reset/correction, do not reuse invalidated readings.
4. For chart facts/personal astrology, calculate from resolved DOB/time/place or
   use this request's verified precomputed evidence. Read the relevant skill for
   exact invocation. Images/PDFs use the existing artifact flow and actual URLs.
   For interpretation use only relevant retrieved principles and checked facts.
5. Answer the question in the selected language and voice. Keep facts, traditional
   interpretation and any conditional forecast distinct. Preserve optional media
   markers; the application owns sending, counting, payment and notification.

## Birth forms

Ask only for missing/conflicting fields when a partial profile exists. Do not
require name, gender or religion to calculate with DOB/time/place. Use the full
form below only for a genuinely new profile, starting directly with its first
line. Each field remains on its own line. For native languages translate the
labels into that same script rather than mixing scripts.

English:
```
Could you please share your details:

Name:
Date of Birth:
Time:
Place of Birth:
Gender (optional):
Religion (Optional):
```

Hinglish:
```
Kripya apni details yahan share karein:

Naam:
Janam Tithi:
Samay:
Janam Sthaan:
Gender (optional):
Dharam (Religion) (Optional):
```

## Special requests

Billing: use the supplied current account status. Do not run charts or replace
payment/access/cancellation questions with a trial pitch. Successful submission
alone does not confirm an action. Preserve the existing supported account flow.

Matching: explicitly select both subjects and calculation roles. Keep each birth
profile separate and confirm consent before sending another person's details to
an external provider. Use the vedastro skill only when enabled and verified.
Its percentage is a traditional provider score, not points out of 36 or a
probability of marriage success. Disabled/error/incomplete results have no score.

Repeat readings: retain supported facts with the same birth and method. Fresh
calculations or corrections can revise them; explain only the actual change.
Do not shame repeated questions or preserve an unsupported earlier prediction.

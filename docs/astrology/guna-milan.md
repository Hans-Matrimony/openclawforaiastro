# Guna Milan calculation

The local `get_match_report` tool now returns `guna_milan` alongside the existing
two-chart observations. It uses each partner's calculated, unrounded **sidereal
Moon longitude**, Swiss Ephemeris and Lahiri ayanamsa. The score is computed in
code, never generated by a language model or inferred from a percentage.

The result includes `score_points`, `score_max: 36`, `display_score`, eight
`factors` with their points and maxima, both Moon attribute records, and base
Nadi/Bhakoot flags. A half point is retained. No model, provider, billing,
single-person reading, friendship prompt or client UI configuration changes.

## Selected convention

Ruleset `astrofriend-north-base-v1` is the **North Indian base Ashtakoota score**.
Traditional schools publish differing Vashya, Yoni and Gana tables; this is an
explicit convention, not a claim that every matching website returns the same
total. The eight maxima are 1, 2, 3, 4, 5, 6, 7 and 8.

Calculation facts were checked against the publisher's [AIFAS *Horoscope
Matching*, third edition (December 2021)](https://www.futuresamachar.com/download/horoscope-matching-325.pdf),
chapters 4–11 and printed reference pages 111–113. This is an independent
implementation; no third-party calculator code or new package is included.

- Varna: Moon water/fire/earth/air categories have ranks 3/2/1/0. Award one
  point when the groom's calculation rank is at least the bride's. This chart
  category must never be used to infer a real person's caste or worth.
- Vashya: the book's **tabular** five-group scores, with Sagittarius split at
  15 degrees (human/quadruped) and Capricorn at 15 degrees (quadruped/aquatic).
  The printed prose example conflicts with its table; this version uses the
  table explicitly. The degree split is also described in [Drik Panchang's
  Vashya calculation](https://www.drikpanchang.com/tutorials/jyotisha/kundali-match/ashta-kuta/vashya-kuta.html).
- Tara: inclusive nakshatra counts in both directions, 1.5 points per direction
  unless the remainder modulo nine is 3, 5 or 7. Zero remainder is favorable.
- Yoni: the fourteen-animal table. Cow/tiger is zero in **both** directions:
  the book has one conflicting cell, resolved using its stated mutual-enemy
  rule and [Saravali's published Yoni table](https://saravali.github.io/astrology/koota_yoni.html).
  Buffalo/lion is one in both directions, following the book's two descriptive
  entries rather than its conflicting matrix cell. Both choices are pinned by tests.
- Graha Maitri: the book's seven-planet natural-friendship point matrix,
  including 0.5 values. Use Moon-sign lords, not temporary natal friendships.
- Gana: the book's tabular bride-row/groom-column scores. Roles are preserved;
  exchanging them can change this factor. Never infer the roles from names.
- Bhakoot: zero for mutual sign relations 2/12, 5/9 and 6/8, otherwise seven.
- Nadi: eight when the nakshatra-based Nadis differ, otherwise zero.

The versioned tables are the arithmetic contract. Do not silently swap a table
or transpose the roles to force agreement with another site.

## Scope and input handling

Both partners require separate exact dates, times and birth cities. Invalid
calendar dates, unknown clock times, substring city matches and conflicting
regions/countries fail rather than receiving invented inputs. The matching
path resolves the existing supported cities using historical IANA timezones;
DST gaps and overlaps require clarification. General chart geocoding is
unchanged. Matching supports dates from 1900 through today, not future births.

This is a **base score**: Nadi/Bhakoot cancellation rules, Mangal dosha, Navamsa,
and relationship predictions are separate assessments, not bonus points.
`exceptions_applied` is false; zero-score flags are not a claim that all possible
cancellations were evaluated. No probability of marriage success is returned.

The optional hosted VedAstro skill remains a different, opt-in percentage-based
calculation. Its percentage must not be converted into these points. The new
36-point result is supplied by the default local matching tool. Tests use
synthetic birth data and make no model/provider calls.
